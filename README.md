# 事前受付 (まとめ QR)

体験の受付を、Host PC から離れた場所で先に済ませるためのスマホ用 Web アプリです。

1. 事前受付の担当者が、スマホのカメラでお客様の会員 QR を順に読みます。
2. 「Host に渡す」を押すと、読んだ人たちが 1 枚の QR (まとめ QR) になります。
3. そのスマホを Host PC の受付カメラにかざすと、全員がまとめて登録されます。

スマホは Host PC と通信しません。受け渡しは画面の QR だけです。

## 使い方

- 公開した URL をスマホの Chrome (Android) か Safari (iPhone) で開き、**ホーム画面に追加**して使います。一度開けば回線が無くても動きます。
- 「カメラを開始」→ 会員 QR を写す → 一覧に名前が出ます。間違えた人は「削除」で消せます。
- 次の回の人を先に読んでおくときは「+ 新しいグループ」で分けます。
- 「Host に渡す」で出た QR を、Host PC の受付パネル (登録先を「次のコマ」か「今のコマ」にした状態) のカメラにかざします。
  5 人以上は自動で 2 枚に分かれ、約 1.5 秒ごとに切り替わります。かざしたまま待ってください。
- まとめ QR の「閉じる」を押すと「このグループを削除して閉じますか？」と聞きます。Host に登録できていれば「削除して閉じる」、
  まだ読めていない・後でもう一度見せるなら「残して閉じる」を選びます。
- 席 (どのゴーグルを使うか) の割当は、今までどおり Host PC の受付パネルで行います。

### 読み取ったリストは消去ボタンを押すまで消えません

リストはこの端末のブラウザにだけ保存されます (どこにも送信しません)。ページの再読み込み、タブを閉じる、端末の再起動、アプリの更新のどれでも残ります。時間が経っても、Host に見せた後でも自動では消しません。

消えるのは次の操作だけです (どれも確認が出ます)。

- 一覧の「削除」(1 人)
- まとめ QR を閉じるときの「削除して閉じる」(そのグループ)
- 「このグループを消去」
- 設定の「すべて消去」

会員の名前と会員コードが端末に残るので、**営業終了時に「すべて消去」を押してください**。

次の場合はブラウザ側の都合で消えます (アプリからは防げません)。

- シークレット (プライベート) ウィンドウで使った
- ブラウザの設定から「サイトのデータを消去」した
- iPhone の Safari で、ホーム画面に追加せずに 7 日以上開かなかった

### 発行日の確認

会員 QR に発行日時が入っている場合、発行日が今日でない QR は「発行日が本日ではありません」と出して受け付けません (お客様に会員ページで QR を表示し直してもらってください)。設定の「発行日が本日の QR だけ受ける」で切り替えられます。発行日時の入っていない QR はそのまま受けます。

### このアプリが確認しないこと

会員 QR の署名は確認しません (鍵を持っていません)。署名・有効期限の確認は Host PC がまとめ QR を読んだときに行い、通らなかった人だけ Host PC の画面に理由つきで出ます。その人は Host PC のカメラで会員 QR を直接読み直してください。

## 開発

ビルド工程はありません。置いてあるファイルがそのまま動きます。

| ファイル | 内容 |
| --- | --- |
| `index.html` / `app.css` / `app.js` | 画面 |
| `codec.js` | 会員 QR の解析と、まとめ QR の符号化 |
| `store.js` | リストの保存 (localStorage) |
| `sw.js` / `manifest.webmanifest` / `icons/` | オフライン動作とホーム画面への追加 |
| `version.js` | アプリの版 |
| `vendor/` | 同梱ライブラリ (QR の読取 jsQR、QR の生成 qrcode-generator) |
| `test/` / `test.html` | 検査 |

### 手元で動かす

カメラは HTTPS か `localhost` でしか使えません。

```powershell
python -m http.server 8765 --bind 127.0.0.1
```

- PC: Chrome で `http://127.0.0.1:8765/` を開く。
- Android の実機: USB でつないで `adb reverse tcp:8765 tcp:8765` を実行し、スマホの Chrome で `http://localhost:8765/` を開く。

### 検査

```powershell
node .\test\run_node.js      # codec.js / store.js (固定ベクタ、保存の約束、QR の大きさ)
node .\test\e2e_chrome.js    # 実際のページを Chrome で通し確認 (上のサーバーを起動しておく)
```

`test.html` をブラウザで開くと、そのブラウザで `codec.js` / `store.js` を検査できます (実機の Safari などの確認用)。

`e2e_chrome.js` は Chrome の偽カメラに会員 QR の映像を流し、読取 → 一覧 → 再読み込みしても残る → まとめ QR の表示 (画面の QR を読み戻して照合) → 消去 → 回線なしでの起動 までを確かめます。

### 変更したら

- **`version.js` の版を必ず上げる。** Service Worker のキャッシュ名に使っているので、上げないと端末に古い版が残ります。版を上げても、読み取ったリストは消えません。
- まとめ QR の形式 (`codec.js`) は、読み取る側 (Host PC) と同じ固定ベクタで検査しています。形式を変えるときは Host 側と同時に変えてください。

### 公開 (GitHub Pages)

リポジトリの Settings → Pages で、公開元をブランチのルート (`/`) にします。ビルドは不要です (`.nojekyll` を置いてあります)。新しい版を push すると、開いている端末には「新しい版があります」と出て、「更新する」を押すと切り替わります。

## まとめ QR の形式 (v1)

文字列 = `MFPR1` + Base32 (RFC 4648、`A-Z2-7`、パディングなし)。全体が英数字だけなので QR の英数字モードに収まります。

Base32 の中身:

| 位置 | 内容 |
| --- | --- |
| 1 バイト | 形式の版 (1) |
| 2 バイト | グループ ID (グループ全体の会員レコード列の CRC16。全ての分割で同じ値) |
| 1 バイト | 分割の番号 (0 始まり) |
| 1 バイト | 分割の総数 (1〜15) |
| 1 バイト | この QR の人数 (1〜16) |
| 人数分 | 長さ (1) + `user_code` (UTF-8) / 長さ (1) + `username` (UTF-8) / `issued_at` (4 バイト、0 = 無し) / `sig` (16 バイト) |
| 2 バイト | CRC-16/CCITT-FALSE (ここまでの全バイト) |

分割は 1 枚ごとに自己完結しています。目安として、2 人で 41 マス角、4 人で 57 マス角、8 人を 1 枚にすると 69 マス角です (`node test/run_node.js` が出します)。
